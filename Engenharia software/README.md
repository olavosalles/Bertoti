Achei interessante a comparação entre engenharia de software e programação. O texto mostra que do mesmo jeito que engenheiros mecânicos, civis, aeronáuticos e de outras disciplinas de engenharia trabalham no mundo real para criar algo concreto, os engenheiros de software também trabalham para construir algo que funcione no mundo real, porem, as vezes com práticas menos rigorosas.

Atividade 2:
---
Achei interessante a ideia de considerar a engenharia de software como uma "programação ao longo do tempo". Isso mostra que não basta criar um código que funcione, é preciso pensar em como ele vai ser mantido e adaptado conforme o projeto e a organização crescem

Atividade 3:
---
1- Consistência vs. Disponibilidade: Escolher entre garantir que todo mundo veja a informação 100% atualizada (mas o sistema pode travar se a rede cair) ou manter o sistema sempre no ar (mas correndo o risco de mostrar dados antigos).

2- Velocidade vs. Custo de Memória (Cache): Usar cache na memória RAM para o app voar e abrir tudo na hora (mas pagar caro em servidores) ou economizar hardware (mas deixar o sistema mais lento).

3- Lançar Rápido vs. Código Limpo: Cortar caminho para colocar a funcionalidade no ar mais rápido (mas gerar dívida técnica e bugs difíceis de consertar depois) ou fazer tudo certinho (mas demorar mais para entregar).
